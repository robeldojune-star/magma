# 팀원 파일 관리 및 보고 규칙

> June님 지시에 따라 팀원 각자가 자신이 생성·수정한 파일을 정리하고 최종 보고서를 제출하는 규칙입니다.

---

## 1. 파일 번호 중복 방지 규칙

### 현재 company/의 번호 충돌
```
02-next-steps.md      ← Oliver 생성
02-work-guide.md      ← Oliver 생성
02_work_guide.md      ← 중복 가능성 높음 (동일 번호 02)
```

### 해결 방법
| 상황 | 처리 방법 |
|------|-----------|
| 동일 번호 파일이 여러 개 | 날짜 접미사로 구분. 예: `02-work-guide-20260628.md` |
| 버전 업데이트 필요 | 파일 내 메타데이터로 버전 관리. 파일명은 유지 |
| 새 파일 생성 | 번호는 기존 파일과 중복되지 않게 부여 |

---

## 2. 파일 상단 메타데이터 의무화

모든 산출물 파일 상단에 다음을 반드시 포함하세요:

```markdown
---
작성자: [이름]
소유자: [이름]
생성일: YYYY-MM-DD
최종수정: YYYY-MM-DD
버전: v0.1
경로: company/파일명.md
---
```

---

## 3. 팀원별 현재 파일 정리 요청

각 팀원은 자신이 생성하거나 수정한 파일 목록을 아래 형식으로 정리해주세요:

```
[작업자 이름]
- 파일: company/파일명.md
- 생성일: YYYY-MM-DD
- 수정일: YYYY-MM-DD
- 버전: v0.1
- 비고: 간단한 작업 내용
```

---

## 4. 최종 보고서 제출

각 팀원은 최종 보고서를 아래 경로에 제출하세요:

**경로:** `reports/YYYY-MM-DD-[작업자명]-work-report.md`

**보고서 형식:**

```markdown
# [작업자명] 최종 작업 보고서

- 작성일: YYYY-MM-DD
- 작업자: [이름/역할]

## 1. 본인이 생성·수정한 파일 목록

| 파일명 | 경로 | 생성일 | 최종수정 | 버전 |
|--------|------|--------|----------|------|
| 예: 05-네이밍-브랜드보이스.md | company/05-네이밍-브랜드보이스.md | 2026-06-28 | 2026-06-28 | v0.1 |

## 2. 작업 내용 요약
(각 파일별로 간단히)

## 3. 번호 중복 발견 사항
(있으면 적고, 없으면 "없음")

## 4. 다음 단계
(필요한 지원이나 리뷰 요청)
```

---

## 5. 제출 마감

**마감일:** 2026-06-29

제출 후 이 채널에 경로만 공유해주세요.

```
[제출] Noah — 최종 작업 보고서
```
