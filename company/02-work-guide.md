## 1. 목적
이 문서는 MAGMA 팀원이 일관된 방식으로 작업하고, 결과를 검증 가능하게 남기기 위한 규칙이다.

## 2. 작업 전 필독
작업을 시작하기 전에 다음 문서를 순서대로 읽는다.
1. 이 문서 (`company/02-work-guide.md`)
2. `company/01-brand-deck.md` — 현재 확정된 브랜드 방향
3. `decision/` — 결정 기록
4. 자신의 `SOUL.md` — 역할과 말투 기준

## 3. 결과물 저장 위치

| 유형 | 경로 | 비고 |
|------|------|------|
| 회사 방향성 | `company/` | 번호_제목.md |
| 결정 기록 | `decision/` | 번호_제목.md |
| 리서치 자료 | `research/` | 원천·보고서 |
| 디자인 리소스 | `design/` | 시안·에셋 |
| 원시 데이터 | `research/data/` | CSV·JSON |

원칙: 모든 결과는 위 경로에 저장한다. 임시 경로(scratch 등)에만 생성하면 완료로 인정하지 않는다.

## 4. 문서 작성 규칙
모든 문서 상단에 다음 메타데이터를 포함한다.
- 작성자 / 소유자 / 작성일 / 최종 수정일 / 버전 / 경로

변경 시에는 본문 하단에 변경 이력을 두고 날짜·변경자·변경 내용을 기록한다.

## 5. Owner(담당자) 표준
standard owner 배치표는 `company/00-작업관리규칙.md`의 2.4 파일별 Owner 매핑을 따른다.
변경·보강·승인 시 해당 파일의 Owner만 수정한다.

## 6. Kanban 작업 규칙
### 6-1. 작업 시작 전
task body를 정확히 읽고 완료 조건을 이해한 뒤 시작한다. 선행 파일이 있는지 확인하고, 불확실하면 확인을 요청한다.

### 6-2. 작업 중
결과는 지정된 경로에 저장한다. 작업 중 막히는 부분은 즉시 comment로 남기고 blocked로 전환한다.
같은 파일을 동시에 여러 task가 수정하지 않는다.

### 6-3. 완료 시
아래 네 가지를 모두 만족해야 complete 처리한다.
1. task body의 완료 조건 충족
2. 결과 파일이 지정 경로에 저장됨
3. `kanban comment`로 다음을 남김: 결과 파일 경로, 변경 내용 요약(3줄 이내), 다음 단계 제안
4. 작성자·날짜·버전 메타데이터가 문서에 포함됨

### 6-4. 검증 규칙
Oliver는 comment를 확인하고 원본 파일을 직접 읽어서 검증한다.
검증 통과하지 못하면 blocked로 전환하고 사유를 comment에 남긴다.

## 7. 금지사항
- 원본 파일을 건드리지 않고 scratch에만 생성하는 행위
- 결과 보고 없이 complete 마크
- 추측으로 채워진 보고서 작성
- "누가 쓴 건지 모르겠다"는 식의 불확실한 상태 방치
