# MAGMA Git-less 운영 규칙

> Git 환경과 별개로, 로컬 파일 규칙만으로 작업이 끊기지 않게 하는 최소 운영 표준.

## 1. 기본 원칙
- push/commit/pull 같은 Git 명령을 **사용하지 않는다**.
- 작업 단위는 **파일 경로 기준**으로 한다.
- 파일명은 ASCII 영어와 `-`만 사용한다. 공백/한글/특수문자는 `_`로 통일한다.

## 2. 폴더 구조
```
/home/june/magma/
  company/        <- 회사 방향성 문서
  research/       <- 리서치 자료
  decision/       <- 결정 기록
  design/         <- 디자인 리소스
  tasks/          <- 작업 지시서
  reports/        <- 진행 보고
  backups/        <- 일일 백업
```

## 3. 작업 흐름 (원본 기반)
1. 작업을 시작하기 전 현재 파일을 그대로 둔다.
2. `tasks/YYYY-MM-DD-<작업명>.md`에 작업 지시를 작성한다(담당/완료조건/산출물 경로).
3. 담당자는 해당 경로의 원본 파일을 직접 수정한다.
4. 완료 후 `reports/YYYY-MM-DD-<팀원>-report.md`에 다음 내용을 기록한다:
   - 변경 파일 경로
   - 변경 요약
   - 검증 방법
5. 점검자는 보고를 읽고 `reports/YYYY-MM-DD-review.md`에 합격/불합격을 남긴다.

## 4. 검증 규칙
- 검증 조건(body 완료조건)이 문서에 명시되어 있으면, 보고 내용이 조건을 충족하는지만 확인한다.
- 불합격이면 원본 파일을 직접 수정해서 재작업 요청한다.
- 2회 이상 불합격 시 작업 방안을 재논의한다.

## 5. 백업 규정
- 매 작업 전 `bash /home/june/magma/scripts/backup.sh`를 실행한다.
- Git push 여부와 무관하게 백업을 우선한다.
- 백업은 `backups/`에 날짜별로 쌓인다.

## 6. 금지
- scratch, tmp 등 임시 경로에 결과물을 두는 것을 금지한다.
- 원본 파일을 삭제하거나 이름을 바꾸는 것을 금지한다.
- 완료 기준 없이 complete 표시를 금지한다.
