## 피드백 정리

### 1. (필수) 카드 작성 5원칙 검증
규칙 v2.0은 카드가 시작 전 5가지 질문에 답해야 하나, 실제 칸반 실행 시 5원칙 검증이 생략되고 있음. 이로 인해 목적·다음 단계·담당자 연결이 누락된 카드가 발생하고 있으니, 카드 생성 전 체크리스트를 도입할 것을 제안한다.

### 2. (필수) Owner 변경 시 Shadow 영향 검증
규칙 v2.0은 Owner 변경에 따라 파일 매핑 표를 함께 수정하도록 규정한다. 현재 04-디자인시스템.md의 Owner는 Mia이므로, Owner 변경이 발생할 경우 다음 영향 파일을 함께 검증해야 한다.
- Shadow 영향: company/02-next-steps.md, decision/005-visual.md, DESIGN.md(토큰)
- 확인 필요: 규정 상 'Owner 변경 시 영향을 받는 파일'을 명시적으로 열거할 것.

### 3. (필수) 검증 의무와 실제 차이 해소
규칙 v2.0은 Oliver의 24시간 내 검토 의무를 규정한다. 현재 Oliver 지시서에 "본 지시서의 완료 조건 3가지가 모두 충족되어야 완료로 인정"과 "팀원들은 Oliver 검토 없이 본 규칙에 따라 자율적으로 작업 진행 가능"이 병기되어 있어, 실제 적용 기준이 불분명하다. 다음 중 하나로 명확히 정리할 것.
  ① Oliver 검토 필수
  ② 검토 없이 자율 진행 가능
  ③ 24시간 미응답시 자율 진행

### 4. (필수) 파일 불일치에 대한 검출·수정 절차 부재
회고에서 지적된 파일 불일치 문제(예: research/08-가격포지셔닝결정서.md vs 확정서.md)는 디자인 규칙의 정합성 검증에도 영향을 준다. 이름을 통일하지 않으면 디자인 토큰을 일관되게 적용하기 어렵다. 즉시 다음을 적용할 것을 제안한다.
- 원본 존재 여부 확인 절차 의무화
- 중복 파일 발생 시 통합 규칙을 규정 섹션 7번에 추가
- 규칙 적용은 변경 후 모든 파일 경로와 변경 이력을 체크리스트에 기록

### 5. (필수) 의존성 기반 보고 플로우
회고에서 지적된 바와 같이 팀 간 보고 체인이 문서에만 존재한다. 실제 동작으로 연결하려면 다음 플로우를 규정에 추가해야 한다.
1) 작업 시작 시 카드 상태를 running으로 전환
2) 작업 완료 시 원본 파일에 결과 반영
3) 카드 댓글로 결과 요약 보고
4) Oliver 또는 리더 검토 (24시간 내)
5) 검증 결과를 READY 또는 수정 요청으로 표시

### 6. (필수) 규칙 버전 관리
현재 규칙 파일이 v1.0과 v2.0이 병존한다. 다음을 적용하여 강제 정리한다.
- 규칙 파일은 company/00-작업관리규칙.md 단일 파일만 유지
- 모든 팀원은 적용 버전을 파일 상단 metadata로 확인
- 변경은 Oliver 주도로 1씩 올린다 (2.0 → 2.1)

### 7. (필수) 규칙 검증 조건 추가
규칙의 별도 섹션으로 '규칙 검증 조건'을 추가해 다음과 같이 기술할 것을 제안한다.
- 규칙 적용 가능성 검증: 변경 시 원본 문서 최신 상태를 먼저 읽어 충돌 여부를 확인한다
- 변경 영향 범위: 영향을 받는 파일·담당자·검증자 목록을 반드시 기록한다
- 회고 요구 문서: 변경 내용만 쓰지 않고 변경 전/후 차이와 이유를 반드시 문서화한다
