## 2. 운영에 반드시 필요한 내용

1. **카드 작성 5문항 의무**
   - ① 왜 필요한가 / ② MAGMA에 어떤 도움이 되는가 / ③ 기존 아이디어와의 관계 / ④ 다음 단계 / ⑤ 이어받을 사람.
   - 5문항이 없으면 규칙 위반.

2. **상태 전이 순서 (강제)**
   - IDEA → RESEARCH → DISCUSSION → DESIGN → BUILD → REVIEW → READY → COMPLETED
   - 순서 건너뛰기 금지.
   - REVIEW 단계에서 파일 존재·품질·메타데이터 검증 → READY.
   - COMPLETED는 최종 반영 확인 후 마지막에 사용.

3. **파일 Owner**
   - 규칙 표에 따라 수정 권한이 정해짐.
   - 미지정 파일은 Oliver 배정.
   - 파일을 건드리기 전 Owner 확인이 우선.

4. **메타데이터 의무**
   - 문서 최상단: 작성자 / 소유자 / 작성일 / 최종 수정일 / 버전 / 경로.
   - 수정 때마다 날짜·버전·변경 이력(날짜·변경자·내용) 업데이트.

5. **COMPLETED 진입 조건 (3가지 모두 충족 필수)**
   - 원본 경로(`company/`, `research/`, `decision/`)에 실제 파일 존재.
   - 문서 최상단 메타데이터 정상.
   - Oliver 검증 완료 또는 Charter 24시간 내 검증 원칙 준수.
   - 조건 미충족 시 COMPLETED 표시는 규칙 위반.

6. **문제 보고 의무**
   - 충돌·권한 오류·파일 손상 발견 시 즉시 Oliver 보고.
   - 자체 판단으로 복구하지 않고 대기.

## 3. 팀원视角 영향

- **속도**: Owner 매핑과 순차 상태 전이가 병목 요인으로 작용할 수 있음.
- **품질**: COMPLETED 전 검증이 강화되어 불완전 산출물 유통이 줄어듦.
- **운영**: 메타데이터·변경 이력이 자동화가 아니므로 수작업 관리 부담 발생.

## 4. 유의사항

1. v1.0(Charter)은 팀 문화의 방향이지만, v2.0(규칙)은 실제 행동 기준입니다. Charter의 "5분 내 이해 가능" 같은 문화 규범은 v2.0에 직접 반영되지 않아 운영자가 연결해야 합니다.
2. 규칙 전파 경로는 Slack 공지 채널 `C0B8U8VK70C`로 고정되어 있습니다. 채널 변경 시 규칙 문서도 함께 업데이트되어야 합니다.
3. 경미한 수정(오타 등)에 대한 owner 자체 조치 허용 기준이 모호합니다. 구체적 예외 기준이 추가되어야 혼선이 줄어듭니다.
4. 검증 주체가 단일 장애점(Oliver)으로 되어 있습니다. 02-next-steps의 24시간 규칙이 보완하지만, Oliver 부재·지연 시 대체 검증 주체(예: 팀 합의 품질 체크리스트)가 필요합니다.
